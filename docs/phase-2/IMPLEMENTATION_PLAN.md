# 第二阶段完整实施计划

## 1. 交付目标

第二阶段交付一个真正可执行的英语学习 Agent，而不只是普通聊天框。模型负责理解用户意图、组织语言和选择工具；后端领域服务负责读取学习事实、计算计划和执行数据变更；数据库保存会话、审计与业务结果。

本阶段完成后，用户可以在一个对话入口中：

- 使用自己配置的 MiniMax 或 DeepSeek 模型连续对话；
- 查询今天、昨天、前天或指定日期实际学习和复习过的单词；
- 查询今日确定计划、明日预测计划和近期易错词；
- 查词、生成适合当前等级的例句和分级文章草稿；
- 新建、重命名、删除生词本，并向指定生词本添加或移除单词；
- 用自然语言打开学习、文章、生词本和设置页面；
- 在刷新、退出和重新登录后恢复历史对话；
- 在桌面和手机上使用同一套完整功能。

PDF、OCR、单词语音和句子语音留在第三阶段。本阶段只保持模型和工具层可扩展，不实现异步文件处理。

## 2. 里程碑与顺序

### M1：Agent 数据底座

- 增加会话、消息、工具执行审计、长期偏好数据表；
- 增加用户时区，所有“今天/昨天/明天”按用户时区计算；
- 增加每日计划及计划项快照，避免复习后无法还原原计划；
- 增加多生词本和关联表；
- 为 AI 生成文章增加用户归属、草稿状态和生成元数据；
- 完成可升级、可降级的 Alembic 迁移。

### M2：模型调用与 Agent 循环

- 扩展统一 Provider 接口，支持普通和 SSE 流式 Chat Completions；
- 归一化文本、Tool Calls、结束原因和 Token 用量；
- 实现最多 6 次模型往返、最多 10 次工具调用的受限循环；
- 对模型返回的工具名与参数执行严格 Pydantic 校验；
- 隐藏推理内容，不把厂商思维链展示或写入普通消息；
- 处理鉴权失败、额度不足、限流、超时和异常响应。

### M3：学习事实工具

- `lookup_word`：查词与学习状态；
- `get_learning_history`：查询指定日期真实学习记录；
- `get_review_plan`：获取今日计划或未来预测；
- `get_difficult_words`：根据错误率与掌握度计算易错词；
- `navigate_to_page`：仅返回允许的站内页面枚举；
- 所有查询按当前登录用户隔离。

### M4：多生词本与写操作

- `list_vocabulary_collections`；
- `create_vocabulary_collection`；
- `rename_vocabulary_collection`；
- `add_word_to_vocabulary_collection`；
- `remove_word_from_vocabulary_collection`；
- `delete_vocabulary_collection`；
- 可重复请求保持幂等，破坏性删除必须经过确认；
- 确认后执行保存的、已经验证过的参数，模型不能在确认后替换目标。

### M5：内容生成与个性化

- `generate_examples`：生成结构化例句与翻译；
- `generate_article_draft`：按等级、主题、目标词生成文章草稿并持久化；
- 对生成结果做字段、长度、等级和句子数量校验；
- 长对话使用摘要控制上下文长度；
- 仅保存明确表达的稳定学习偏好，不把临时聊天自动当作长期记忆。

### M6：AI 首页和对话界面

- 首页展示今日计划概览、快捷问题和主要对话输入框；
- 独立对话页包含历史会话、流式消息、停止生成和错误重试；
- 展示单词、学习计划、生词本、文章等结构化工具卡片；
- 危险操作展示确认/取消卡片；
- 收到受限导航事件后由前端路由器跳转；
- 移动端使用抽屉式会话列表和底部输入区。

### M7：测试、实测与交付

- 后端领域服务、工具注册表、Agent 循环和 API 集成测试；
- Provider SSE 与 Tool Call 分片解析测试；
- 前端 lint、类型检查和生产构建；
- Alembic 从初始版本升级到最新、降级一个版本再升级；
- Docker Compose 配置检查和敏感信息扫描；
- 使用仓库外的测试 Key 对 MiniMax-M3 完成模型列表、普通回答、流式回答和 Tool Call 实测；
- 清理临时数据库、临时配置和测试凭证。

## 3. 数据模型

| 表 | 关键数据 | 作用 |
|---|---|---|
| `ai_conversations` | 用户、标题、厂商、模型、摘要、归档时间 | 会话列表与上下文恢复 |
| `ai_messages` | 角色、内容、Tool Calls、用量、时间 | 完整对话事实 |
| `ai_tool_runs` | 工具、参数、状态、结果、幂等键、确认时间 | 权限控制与审计 |
| `ai_user_memories` | 用户、偏好键和值、来源 | 稳定的长期学习偏好 |
| `daily_study_plans` | 用户、日期、时区、算法版本 | 每日计划快照 |
| `daily_study_plan_items` | 单词、类型、顺序、完成时间 | 计划明细与完成状态 |
| `vocabulary_collections` | 用户、名称、描述、默认标记 | 自定义生词本 |
| `vocabulary_collection_items` | 生词本、生词条目 | 多对多分类 |

现有 `vocabulary_items` 继续表示“用户拥有这个生词”，同一生词可以属于多个生词本。删除生词本只删除分类关系，不删除单词学习进度。

## 4. API 契约

### 会话

- `GET /api/v1/ai/conversations`：会话列表；
- `POST /api/v1/ai/conversations`：创建会话；
- `GET /api/v1/ai/conversations/{id}/messages`：消息历史；
- `PATCH /api/v1/ai/conversations/{id}`：重命名或归档；
- `DELETE /api/v1/ai/conversations/{id}`：删除当前用户会话；
- `POST /api/v1/ai/chat/stream`：发送消息并以 SSE 返回 Agent 事件；
- `POST /api/v1/ai/tool-runs/{id}/confirm`：确认或取消待执行操作。

### SSE 事件

| 事件 | 内容 |
|---|---|
| `conversation.created` | 首次消息创建的会话 ID |
| `message.delta` | 助手文本增量 |
| `tool.started` | 工具名与执行 ID |
| `tool.completed` | 可展示的结构化结果 |
| `tool.failed` | 安全化错误信息 |
| `confirmation.required` | 待确认操作摘要 |
| `navigation.requested` | 允许页面枚举及参数 |
| `message.completed` | 最终消息 ID 和完整文本 |
| `usage.completed` | 厂商、模型、Token 和耗时 |
| `error` | 可恢复或不可恢复错误 |

## 5. 安全与权限规则

- Provider API Key 永远不进入 Git、浏览器存储、日志、消息或审计结果；
- 每次数据库查询都使用当前认证用户 ID 过滤；
- 工具只能来自静态注册表，不允许任意 SQL、HTTP、文件和代码执行；
- 导航只允许 `home`、`learn`、`articles`、`article`、`vocabulary`、`profile`；
- 新建、重命名和添加属于可撤销写入，可在明确意图下执行；
- 删除生词本和批量移除属于破坏性操作，必须确认；
- 工具调用使用幂等键，网络重试不会重复写入；
- 单轮达到步骤、工具数量或耗时上限时安全停止并提示用户缩小请求。

## 6. 每日计划定义

- “今天的计划”首次查询时按当时到期复习词和每日新词目标生成快照；
- 完成学习后只更新计划项完成状态，不重写原计划；
- “明天的计划”是根据当前 `next_review_at` 和今日剩余任务计算的预测，回答中必须标注可能变化；
- “昨天学习了什么”只查询 `study_reviews.reviewed_at` 的用户本地日期，不由模型估算；
- 易错词综合近期 `again/hard` 比例、掌握度和重复次数排序。

## 7. 验收矩阵

| 场景 | 验收标准 |
|---|---|
| 连续对话 | 刷新后会话和消息仍存在，厂商/模型可追溯 |
| 学习历史 | 跨 UTC 日期边界仍按用户时区返回正确数据 |
| 明日计划 | 返回预测标记，不虚构确定任务 |
| 添加生词 | 真实写入目标生词本，重复调用不重复 |
| 删除生词本 | 未确认不执行，确认只删除原始目标 |
| 页面导航 | 只能跳到白名单页面，不能接受任意 URL |
| 内容生成 | 例句/文章通过结构校验，文章以个人草稿保存 |
| 用户隔离 | 用户 A 无法查看或操作用户 B 的会话、生词本和计划 |
| 密钥安全 | API 响应、日志、Git diff 和构建产物不出现明文 Key |
| 响应式 | 360px 手机宽度与桌面宽度均可完成主要流程 |
| 真实模型 | MiniMax-M3 普通、流式和 Tool Call 三项实测成功 |

## 8. 完成定义

只有以下条件全部满足才视为第二阶段完成：

1. M1 到 M7 功能代码均落地；
2. 数据迁移可重复执行并有回退验证；
3. 后端自动化测试全部通过；
4. 前端 lint 和生产构建通过；
5. Docker Compose 配置校验通过；
6. MiniMax-M3 真实测试通过，或已明确定位为账号权限、额度或厂商故障并提供用户操作步骤；
7. 仓库无明文凭证和临时测试文件；
8. 开发、配置、测试和部署说明已同步更新。
