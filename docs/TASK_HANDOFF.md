# 跨对话任务交接

本模板用于工作中断、换电脑、换模型或由其他开发者继续任务。交接不是聊天摘要，而是下一位执行者可以验证的事实包。

## 1. 交接原则

- 写具体文件、提交、命令和结果，不写“基本完成”“应该没问题”。
- 区分已完成、进行中、阻塞、未开始和刻意未触碰。
- 未提交改动必须逐项说明；秘密、Token 和用户数据不得进入交接。
- 记录失败尝试和原因，避免下一位重复破坏性操作。
- 需求或决策变化同步更新项目正式文档，不能只留在交接记录。

## 3. 接手检查

接手者按顺序执行：

1. 阅读 `AGENTS.md`、`docs/README.md`、`PROJECT_STATUS.md` 和专项文档。
2. 运行 `git status --short --branch`、`git log -5 --oneline --decorate`。
3. 将实际工作区与交接内容比对；不一致时先停下确认。
4. 打开交接列出的关键 diff、测试和失败日志，不从头猜实现。
5. 先复现最近验证或阻塞，再继续改动。
6. 完成后更新测试证据和正式文档，删除已经失真的临时交接副本。

## 4. 建议保存方式

- 临时跨对话：把模板填好放在任务说明或 PR 描述中。
- 需要随分支保留：可在 `docs/handoffs/<date>-<slug>.md` 创建临时文件。
- 合并前：把长期事实归并到 `PROJECT_STATUS.md`、`DECISIONS.md` 或专项文档；纯临时交接可删除。
- 已完成任务的权威历史优先使用 Git commit/PR，而不是无限累积交接文件。

## 5. 阻塞的准确含义

只有在缺少必须的用户选择、凭证、生产权限、外部授权或无法替代的环境时才标为 blocked。测试失败、实现困难或需要继续调查通常是进行中，不应伪装成外部阻塞。
