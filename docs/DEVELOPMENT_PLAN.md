## 开发节奏建议

- 每个功能使用短分支，完成后合并到 `main`。
- `main` 始终保持可部署；部署前执行后端测试和前端构建。
- 数据模型变化先备份，再通过迁移脚本执行。
- 每周至少一次把服务器备份下载到本地。

## 完成定义

- 第一阶段所有验收场景均有可运行实现，不以静态原型代替。
- 后端测试、数据库迁移和演示数据初始化通过。
- 前端 ESLint、TypeScript 与生产构建通过。
- 生产依赖无 npm 已知漏洞，Compose 配置可以解析并构建。
- 仓库不包含密钥、运行数据库、上传内容或构建缓存。
