## 阶段 2：AI 增强（后续）

1. 抽象模型提供商与结构化输出校验。
2. 根据水平、主题、生词生成分级文章。
3. 解释长难句、语法和上下文词义。
4. 基于学习历史提出每日计划；后端规则校验后采用。
5. 增加调用额度、缓存、重试和成本统计。

## 阶段 3：文档与多媒体（后续）

1. 文本型 PDF 抽取和分段。
2. 扫描 PDF 与图片 OCR，单机任务串行限流。
3. 单词与句子 TTS 缓存。
4. 上传大小、类型、配额和清理策略。
5. 数据量增长后再评估 Redis/任务队列和对象存储。

## 开发节奏建议

- 每个功能使用短分支，完成后合并到 `main`。
- `main` 始终保持可部署；部署前执行后端测试和前端构建。
- 数据模型变化先备份，再通过迁移脚本执行。
- 每周至少一次把服务器备份下载到本地。

## 完成定义

- 第一阶段所有验收场景均有可运行实现，不以静态原型代替。
- 后端测试、数据库迁移和演示数据初始化通过。
- 前端 ESLint、TypeScript 与生产构建通过。
- 生产依赖无 npm 已知漏洞，Compose 配置可以解析并构建。
- 仓库不包含密钥、运行数据库、上传内容或构建缓存。
